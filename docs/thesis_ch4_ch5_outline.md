## 第 4 章 布局引擎与自绘分页编辑器的设计与实现

### 4.1 问题与目标

- 双路径问题：编辑用 `QTextDocument`，若预览/PDF 另用几何估算，页数易分叉
- 目标演进（阶段划分）：
  - 0：DocumentModel（布局/导出的规范视图）
  - 1：LayoutEngine → 预览 / PDF（引擎分页）
  - 1+：活页页数与引擎对齐（早期方案：引擎断点驱动 QTextEdit 页缝——**假分页，最终被放弃**）
  - 2：Model → DOCX 导出
  - 3：**自绘分页编辑器**（本版核心）：编辑视图本身就是真实分页，引擎回归「预览/PDF/导出」
- 放弃 1+ 假分页的原因（作为动机写入 4.1 或 4.7）：
  - 页缝观感突变、文字与页脚重叠
  - 编辑与导出两套布局，行边界差异无法收敛

### 4.2 总体架构（最终版）

```text
QTextDocument ──分页页尺寸 = 页面内容框──► PagedEditorWidget（自绘分页编辑：逐页裁剪绘制 / hitTest / IME / 选区）
        │
        └─ QTextAdapter → DocumentModel
                             ├─ LayoutEngine → 预览 / PDF / 导出分页与绕排
                             ├─ DocxExporter → 内置 DOCX 保存（阶段 2）
                             └─ DocxImporter ← 内置 DOCX 打开（适配层）
```

- 关键取舍：**编辑器分页以 QTextDocument 为准，引擎只管预览/PDF/导出**；两者断行同源（均出自 Qt 排版），行边界基本一致，页数口径各自明确
- 阶段 1+ 的「页数已与引擎对齐」主张随之修订为「断行同源 + 导出/预览由引擎统一分页」

### 4.3 DocumentModel

- 块：段落 / 表格；段落内 Run（文本、样式、原子图）
- 文档偏移（`documentPosition`）：导出与分页锚点基础
- 设计取舍：够用的排版语义，避免过早做成完整 DOM

### 4.4 QTextAdapter（适配层）

- `QTextDocument` → Model 的单向转换
- 覆盖：颜色、图片资源、表格单元格（含合并）
- **导入不对称**：打开 DOCX 仍为桥接 / `DocxIO::load` → Qt；论文中明确「导出阶段 2、导入仍适配层」

### 4.5 LayoutEngine

- 断行：`QTextLayout`（与系统文本度量一致）
- 分页：按内容盒高度切页；表以**行**为原子；图为原子块
- 输出：`LayoutPage` 列表 + `startDocPos` / `pageBreakDocPositions`
- 现状：仅服务预览 / PDF / 导出；不再参与编辑视图的页数与页缝
- 局限：复杂表跨页（单元格纵向拆分）、分栏、脚注等未做或不完整

### 4.6 绘制与接线（预览 / PDF）

- `LayoutPainter` / `PageDocumentPainter`：预览与 PDF，页眉页脚、页号由同一设置绘制
- 与编辑器的关系：断行同源 → 行边界基本一致；复杂文档（多页表、绕排）允许细微差别（论文如实交代边界）

### 4.7 自绘分页编辑器（核心新增）

- **为什么 QTextEdit 不可行**：QTextEdit 强制文档连续流（`pageSize` 高 = -1），无法承载真实分页——这是选择自绘的根本依据（可在 4.7 开头用一小段实验说明：设置分页页高后重排即被覆盖）
- 设计：
  - 页面 = 内容框（宽 × 高）；`QTextDocument::setPageSize` 真实分页
  - 逐页裁剪绘制（`paintContext.clip` + 平移），只画可见页
  - `hitTest` 定位光标；光标/选区/输入法由控件自绘管理
- 关键机制（本设计的难点与解法）：
  - **Qt 断页怪癖**：放不下的行被顶到页底、下一页从「页高 + 该行高」开始 → 布局页高取「内容高 − 最大行高」，行级归属（`PageRange`）保证无行穿越页框
  - 跨页块与边界 off-by-one：增量重建时回退一页继续，避免误触全量
  - 图片：`PagedImageObject` 像素图缓存 + 加载时资源降采样（≤2048px / 2×显示尺寸）
  - 浮动文本框、表格列宽拖动、网格线等编辑交互

### 4.8 增量分页（性能关键）

- 朴素方案：每次编辑全文重排 + 全量遍历算页区间 → 实测 **80 万字约 511ms/键**（O(n)）
- 增量方案：
  - `markDirty`：只记录编辑块
  - `ensureRangesThroughPage`：按需重建受影响页区间（缓存未改动前缀）
  - 120ms 空闲防抖全量补齐页数/滚动条；40ms 判定窗区分「真格式变更」与普通编辑
  - 页面计数在打字期间为估算、停顿后精确（与 Word 延迟分页行为一致）
- 实测：**80 万字尾部逐键 0.07ms、中部逐键 6.8ms**
- 附：编辑路径上的两个 QTextDocument O(n) 病理与对策（均有实验支撑）：
  - HTML 导入的巨长单段落：编辑退化为 O(n) → 文档规范化重建（cursor API 重排）修复
  - 全量排版后的插入开销：增量策略 + 按需查询规避

### 4.9 阶段 2：Model → DOCX

- `DocxExporter`：内置保存路径不经 HTML
- 与桥接（html2docx）的主备关系；失败回退策略
- 作为加分项：证明 Model 不仅服务分页，也服务持久化

### 4.10 本章小结

- 两条线均成立：引擎（预览/PDF/导出）+ 自绘分页编辑器（真实分页 + 增量性能）
- 阶段 3 从「非目标」变为「核心贡献」，叙事闭环

## 第 5 章 实验评测与结果分析

### 5.1 评测目的

- **性能**：量化自绘编辑器在「打开 / 逐键编辑 / 重绘」三方面的大文档表现，验证增量分页的有效性
- **正确性**：跨页打字、页边界、文本框/公式/表格等交互回归（52 个用例 + 初始化/清理，56 个槽）
- **一致性**：预览/PDF 由引擎分页、编辑器断行同源，页数口径明确（保留 v1 的引擎评测）

### 5.2 性能评测方法

- 工具：`NewWordBenchEditorPerf`（自绘编辑器真实组件路径）、`NewWordBenchMixedDoc`（编辑缓冲 QTextDocument）；offscreen、Debug 构建、可复现
- 指标：打开（setHtml + 首次分页）、尾部逐键、**中部逐键**（最坏位置）、表格内逐键、整页重绘

### 5.3 性能结果（基准表）

| 文档 | 打开 | 尾部逐键 | **中部逐键** | 表格内逐键 | 整页重绘 |
|---|---|---|---|---|---|
| 200k 字符（≈126 页）纯文本 | 145ms | 0.03ms | **1.6ms** | — | — |
| 200k 字符 + 200 图 + 200 表 + 1.5 万格式碎片 | 328ms | 2.1ms | **69ms** | 127ms | — |
| 800k 字符（≈500 页）纯文本 | 595ms | 0.07ms | **6.8ms** | — | — |
| 800k 字符 + 1112 张大图（≈1670 页） | 852ms | 0.20ms | **22ms** | — | **2.9ms** |

- 结论：纯文本/格式整齐文档，80 万字内中部编辑在 60fps 预算内；大量表格/碎片化格式时编辑缓冲的 O(n) 失效范围成为边界（架构边界，非控件缺陷）

### 5.4 优化前后对比（论文亮点数据）

- 增量分页：80 万字**中部逐键 509ms → 6.8ms**（约 75×），尾部逐键 511ms → 0.07ms
- 图片重绘：像素图缓存 + 资源降采样后**整页重绘 280ms → 2.9ms**
- 全量分页从每键执行改为空闲防抖：打字不阻塞、页码短暂估算后精确
- 用同一基准工具在每次优化后复测，保证可复现

### 5.5 一致性验证（阶段 1 成果保留）

- 指标三源：几何估算、活页（旧方案）、LayoutEngine；`pagination_eval.md` 为证据
- Δ活页 = 活页 − 引擎（旧方案，接受标准恒为 0）；Δ几何 = 引擎 − 几何（短样例 ≤1 / 长文·图·多页表 ≤3）
- 修订说明：编辑器改版后「活页」已由 QTextDocument 分页取代，旧评测作为阶段 1 的独立成果引用，不再用于当前编辑视图

### 5.6 功能与正确性测试

- 按主题拆分后的测试结构：`tst_coresmoke_docx`（23 项）、`_engine`（20 项）、`_editor`（5 项）共 48 个用例，另有 `tst_documenttab_smoke`（4 个用例）
- 覆盖：DOCX 往返、引擎分页、跨页打字（页边界不变量）、文本框渲染/拖动/编辑、公式对齐与双击编辑、IME 上屏格式、网格与列宽拖动
- 性能基准亦纳入回归（bench 数据不得回退）

### 5.7 威胁效度与局限

- 字体固定 Helvetica 12pt、A4；未覆盖全部中文字体度量差异
- 表不拆单元格；极复杂 Word 文档不在范围
- 导入路径未对称成 `DocxImporter ← Model`
- 超长单段落、极端大图组合仍是 Qt 排版与内存的上限（已通过规范化/降采样缓解）

### 5.8 本章小结

- 主线结论：自绘分页编辑器 + 增量分页达到「大文档编辑可用」的性能目标；引擎在预览/PDF/导出侧保持统一
- 后续工作：编辑缓冲自研（rope + 增量排版，参考 RWord 方向）、导入对称、评测样例扩展

## 写作提示（落地用）

1. **第 4 章以架构图 + 模块职责为主**，少贴大段代码；关键机制（Qt 断页怪癖、增量区间）配 1～2 张小图（页区间示意、增量重建流程）
2. **第 5 章以基准表 + 优化前后对比为核心证据**，文字解释「511ms → 6.8ms」的构成（全文重排 → 按需重建 → 空闲补齐）
3. 阶段划分放在 4.1 或绪论回顾：0 模型 → 1 引擎 → 1+ 活页对齐（放弃）→ 2 导出 → 3 自绘编辑器（完成）
4. 演示建议：打开 80 万字长文 → 中部连续打字（无卡顿）→ 滚动翻页 → 导出 PDF 对照；对比优化前的卡顿（可录屏前后对照）
5. 诚实边界：编辑/导出断行同源但页数口径不同；复杂文档行边界允许细微差别——避免「完全 WYSIWYG」的过度声明
